# Extraction evaluation dataset (Stage 3, step 10)

A small, manually verified set of invoice PDFs plus their ground-truth field
values. It exists to **measure extraction accuracy** before choosing confidence
thresholds or a real provider (steps 11 and 13).

## Why it is synthetic

Real invoices carry third-party and personal data and unclear licensing. Every
PDF here is generated by [`generate_invoices.py`](generate_invoices.py) from the
values in [`expected.json`](expected.json), so the dataset is unambiguously safe
to commit and redistribute, and the files can never drift from the manifest.

Regenerate after editing the manifest:

```bash
# from backend/
python -m evaluation.generate_invoices
```

## Contents

| id | category | notes |
|----|----------|-------|
| `digital_basic` | digital | one page, all fields, single line item |
| `digital_multi_line_items` | multi_line_items | three line items, subtotal = their sum |
| `digital_multi_page` | multi_page | header/totals on page 1, line items on page 2 |
| `digital_incomplete` | incomplete | genuine invoice missing optional fields (`null`) |
| `digital_unusual_layout` | unusual_layout | odd number/date formats, a non-date due term, reordered labels |
| `scanned_no_text` | scanned | rasterized invoice with known contents but **no text layer** - needs OCR/vision |
| `low_quality` | low_quality | truncated/corrupt bytes — must be rejected |
| `not_an_invoice` | not_invoice | readable PDF that is plainly not an invoice |

## Manifest shape (`expected.json`)

Each entry:

- `id`, `file`, `category`, `notes`
- `is_invoice` — is the document actually an invoice
- `readable` — can the PDF be parsed at all
- `text_layer` — `DIGITAL` | `ABSENT` | `UNREADABLE`
- `expected` — ground-truth field values, or `null` when there is nothing to
  extract (`low_quality`, `not_an_invoice`). Every value is a raw string exactly
  as it should be read from the page; genuinely absent fields are `null`. Dates
  stay raw (no reformatting); currency is the 3-letter code.

## Using it

```python
from evaluation.dataset import load_cases

for case in load_cases():
    ...  # case.path, case.expected.as_contract_payload(), case.text_layer, ...
```

`ExpectedInvoice.as_contract_payload()` returns the ground truth in
`InvoiceExtraction` shape (`{"value": ..., "confidence": null}` per field), ready
to diff against a provider's output.

### Scoring

```python
from evaluation.scoring import score_run

report = score_run({case_id: predicted_invoice_extraction_or_None, ...})
print(report.format_summary())
report.field_accuracy, report.critical_field_accuracy, report.line_item_field_accuracy
report.by_category  # per-category breakdown
```

`scoring.py` compares **values only** (confidence is the provider's own estimate,
judged separately — see `docs/provider-selection.md`). Text is
case/whitespace-insensitive, amounts compare numerically, dates and ids compare
verbatim, `None` matches only `None`. Cases with no ground truth (`low_quality`,
`not_an_invoice`) are recorded but not scored; a missing prediction for a scored
case counts every field wrong. Step 12 runs the real adapter over `load_cases()`
and feeds the predictions here.
